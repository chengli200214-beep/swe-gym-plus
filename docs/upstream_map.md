# Upstream map and ownership

| Layer | Upstream choice | CodeAgentBench-owned boundary |
|---|---|---|
| Tasks | SWE-Gym / SWE-Gym-Lite row shape | normalized manifest, revision, grouped split and leakage checks |
| Evaluation | SWE-Bench-style `FAIL_TO_PASS` / `PASS_TO_PASS` | fresh workspace, patch application, structured verdict and logs |
| Agent loop | mini-swe-agent bash interaction | model/action protocol, receipts, recovery, budget and context |
| Model | DeepSeek API-compatible endpoint | usage capture and no-secret artifact policy |
| Storage | filesystem artifacts | atomic checkpoints, append-only events and run index |
| Service | optional FastAPI | task/run/result endpoints; no chat UI |

The checkout at `../upstream/testzeus-hercules` is preserved as an unrelated
reference. Browser navigation, Playwright DOM recovery, order fixtures and
LightGBM ranking are deliberately outside this project's core.

## Data contracts

- `TaskRecord` is the normalized row and owns `EvalSpec`.
- `AgentTaskView` is generated by `TaskRecord.agent_view()` and has no
  `gold_patch` field.
- `CandidateSelector` can inspect a candidate's diff, visible test evidence,
  tool errors and cost. It cannot inspect formal evaluation labels.
- `Evaluator` runs in a new workspace and is the only component that consumes
  the evaluation specification.

## What is still an external prerequisite

The real SWE-Gym and SWE-Bench source revisions must be recorded in
`upstream.lock.yaml` before a benchmark run. The code can import a local
JSON/JSONL/YAML export today, or use the optional Hugging Face `datasets`
adapter. This avoids silently treating a moving dataset revision as a result.
