# ADR 0009：取消请求必须到达持有工具进程组的监督器

状态：已实现并通过同机实际验收；日期：2026-09-27。

## 证据与问题

AutoDL 服务实际验收 01 中，排队取消和示例补丁独立测试通过，但运行取消失败：
队列已显示 cancelled，仍有该工作区 UID 的非僵尸进程。旧记录保留。
Worker 给 CLI 进程组发 SIGTERM；CLI 仅在动作之间检查取消。
NsJail 监督器创建了独立进程组，CLI 随后被强制停止时，它的 finally 清理无法执行。
因此，仅验证队列状态不能证明资源释放。

## 决策与边界

- CLI 使用进程局部的 SIGTERM 作用域，结束时恢复原处理器；无模块级取消状态。
- AgentRuntime 和独立 Evaluator 显式传递取消谓词到 BashExecutor、NsJail、run_bounded。
- 监督器每至多 0.1 秒观察取消，包括 stdout/stderr 已关闭但进程仍运行的情况。
  取消时终止自己创建的进程组并 wait；回调异常也走相同的 finally 清理。
- 取消回执保留实际部分输出，status=cancelled；Runtime 不再请求下个模型动作。
  独立评测以 blocked / formal evaluation cancelled 记录，不算模型测试失败。
- 运行和评测都覆盖；Worker 的最后一次队列检查处理取消与子进程退出的竞态。
- 该动作内协作取消适用于显式 NsJail 后端。local 仍仅供可信示例，bwrap 不因本变更
  获得新的动作内协作取消能力。不降低沙箱策略、不回退宿主执行、不开放公网端口。

## 验证与回滚

单元测试覆盖信号作用域、真实取消回执、评测标签、启动前取消、开放/关闭输出管道的
进程组释放及回调异常清理。同机 API + Worker 验收分别检查模型工具与独立评测中的
活跃 UID 进程消失，以及已确认动作的恢复不重复执行。示例均为可信脚本，非模型成绩。
回滚应整体回退该调用链并禁用运行中服务取消，不能保留只改变队列状态的虚假成功。
SIGKILL、宿主宕机及模型生成中的中断不由该协作谓词保证，仍需外部进程监督与
保守的未知动作恢复拒绝；禁止将本验收宣称为任意故障下的 exactly-once。

同机验收 03 的工具/评测取消耗时分别为 0.314 / 0.516 秒，剩余活跃 guest 进程为 0。
故障注入位于已确认 edit 回执之后，恢复后该 edit 的 intent/receipt 各一份，独立示例
评测通过。全量回归 261 项通过、0 跳过，包含 7 个实际服务用例和 live NsJail 准入。
